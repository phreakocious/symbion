1. Say in two sentences what symbion is: a notebook and ticket registry kept beside the repo, in a git repo of its own; each new session starts with the open bugs, tasks and questions, and a trap filed on a file reaches the agent when it opens that file. Then say what setup does: install the CLI if needed, make the project's store, bring in the project's open threads, and open the browser view.
2. If the repo line above is not a path, say that the store needs a git repository, and stop. Nothing was written.
3. The CLI. This plugin needs symbion 0.13.0 or later, on Python 3.11 or later. Not installed: plan `uv tool install --python '>=3.11' 'symbion[gui]'` when `uv` is on PATH (uv may download a Python into its own directory; say so), else `pipx install 'symbion[gui]'`, with `--python` naming a 3.11 or later when `pipx environment --value PIPX_DEFAULT_PYTHON` is older. Older: plan `uv tool upgrade symbion` or `pipx upgrade symbion`, whichever installed it. With neither uv nor pipx, say so, point to https://github.com/phreakocious/symbion#install, and stop. Never run pip into a system Python.
4. The store. With the CLI installed, run `symbion init`, without `--yes`: it lists each change and makes none. Show that list, less its note that the plugin carries the skill and the hooks. Without the CLI, say what it does by default: it creates the store `../<repo>-notes`, a git repo beside this one, and writes nothing into this repo. Adoption will turn on the `file` catalog in its `symbion.toml`. Setup itself adds one line to `CLAUDE.md`: `- We use symbion for durable notes and tickets.` Where `CLAUDE.md` is gitignored or someone reviews every change to it, propose the line instead of writing it.
5. Ask for approval of steps 3 and 4 at once. First list, in your message, each path and what is written there: a question dialog alone hides it. The store is outside this repo, so Claude Code may ask permission for its writes too. On no, stop: nothing was written. On yes, install, then run `command -v symbion`. If it finds nothing, the install's bin dir is not on PATH: say where the command went, use its full path for the rest of setup, and ask before any change to a shell's rc file (`uv tool update-shell`, `pipx ensurepath`); the hooks find symbion only in a Claude Code started from a shell whose PATH has it. Then, in a call of its own, run `symbion init` again without `--yes`. If its list differs from what you described, show the difference and ask again. Otherwise run `symbion init --yes` and write the `CLAUDE.md` line.
6. Adoption. If `symbion list --limit 1` shows an entry, first ask whether to look for what the store lacks (notes kept before the plugin, a handoff since); on no, go to 8. Read `adoption.md` in the directory `symbion skill --path` prints, and follow it, leaving out what an entry holds: scout the TODO files, handoff notes, Claude Code memory and the git log since the last handoff, then build the candidate table and the list of sources to retire, naming each file and what happens to it.
